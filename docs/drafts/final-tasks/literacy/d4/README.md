# リテラシー 成果物4（上限20点）: 申込から補欠を決めて、補欠のお知らせを出す

作成日: 2026-09-29。状態: 案（未承認）。申込・正解・隠しテストは `make.py` で作り、`verify.py`（kit のルールと申込CSVだけから別の書き方で数え直す）で40版すべて一致を確かめた（NG 0）。

## 1. 20点の人は何ができるか

引き継いだ運用ルールと申込データから、テスト送信・締切後・取消・同じ人の送り直しを式で除いて人数を出し、「いちばん新しい有効な回答の時刻」の先着順で参加確定と補欠を決め、前任者の下書きの誤りだけを過不足なく直して、補欠の方に BCC で予約送信し、返信は Google フォームで自動記録される形まで、40分以内に一人で仕上げられる。

元案（指揮役）「フォーム・スプレッドシート・Gmail をつないで、申込の後始末をする」を、補欠のお知らせという1つの仕事にまとめた。
成果物3（15点）からの積み上げ: 数えるだけでなく**順番（先着順）を決める**。式で数えることは、データを足す・1行を変える・翌週のデータに貼り替える、の3通りで確かめる。文章は「作る」から「誤りだけを直す（直しすぎない）」に変わり、フォーム→スプレッドシート→Gmail がデータとリンクでつながる。
最終課題（30点）への練習: 最終課題の罠のうち、締切の時刻・大文字と空白の同じ人・取消・テスト送信の除外、補欠の人数、最新の回答の時刻での先着順、下書きの曜日・人数・共有・BCC の訂正、誤検出ゼロ、メール本文を1字も変えずに直すこと、をここで一度通す。最終課題で初めて出るのは、表記ゆれ（「1回目」「第１回」）、後ろにある定員の改定、印刷費の計算、録画・画像・名簿の訂正、30分の目標だけにした。

## 7. AIに丸投げした学生は何点になるか（見込み、未検証）

kit と CSV を AI に貼って答えを聞き、値を打ち込む場合: 基礎・段1（共有）・段14（フォーム）・段15（宛先と予約）は本人の操作なので取れる（7点）。行06・10・11 はルールを読めば分かるので段11・12 も取れることが多く（＋2点）、行04 も R1 に曜日が書いてあるので段9 が取れやすい（＋1点）。値を打ち込むので段6〜8 は必ず✖、29行を目で数えるので段2〜4・10 はずれやすく、順番の表（段5）も並べ方がずれやすい。AI は行03 の「！」や行12 の日付を直したがるので段13、本文を書き直すので段16 も✖になりやすい。ここまでで**約10点**（人数が偶然合えば段2・3・10 が加わり13点まで）。コードを実行できる AI に式を書かせ、最新の時刻で並べることを自分で確かめた学生だけが段4〜8 を取れる。使う前に教員が Gemini 無料版で07番を丸投げして確かめること【未検証】。

## 8. コピーした学生はどうなるか

- 他人の番号のシートを出す: シートの名前か版の履歴で基礎が✖、**0点**
- 答えだけ聞き写す: 行06・10・11 の直し方と「訂正は5行だけ」は全版共通なので段11・12・13 が取れる。日付・定員・人数・アドレスは番号で違うので段2〜5・9・10・16 は✖。本人の操作の基礎・段1・段14・段15 と合わせて**10点**。第1回の日付が同じ版（40版で10通り、07番と同じ11月18日は07番を含めて6版）なら段9 も入り11点
- 他人の**式**を写す: 式は番号に依存しないので、段2〜8 がそのまま通る。録画で入力の様子は見えるが、式を人に聞いて打つことは防げない（§9）
