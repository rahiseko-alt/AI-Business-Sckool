# 第2ラウンド全ボツの原因（指揮役のダメ出し、2026-09-28）

根拠は利用者の発言（`docs/knowledge/history/philosophy.md` と本セッションの発言）。

## 致命的な誤り

1. **3科目を同じ番号・同じ相手で縛った**。利用者は「3教科は直接連携していない」「それぞれ独立して評価する」と言っている。つながりは中身が自然につながる所だけでよい。縛ったせいで、前工程の未提出・回数差・級友の欠席という壊れ方をすべて抱え込んだ。
2. **逆算の起点が違う**。利用者の指示は「何のツールを使って、どんなビジネスシーンで役に立つのか、そこから逆算しろ」。3案とも「相手の距離」という物語から組み、場面は学内・級友・生活管理にとどまった。ビジネスの場面になっていない。
3. **成果物として成立していない**。記録・メモ・確認報告・合意書が多い。特にリテラシーは5個とも「確認の紙」で、それ単体で仕事の道具として使える物になっていない。
4. **らせんが見えない**。科目の中で、前の成果物のどの技能を使い、何を新しく足すかが一本の線になっていない。必須7種の積み上げも科目ごとに設計されていない。
5. **上の層の伸びしろが他人任せ**。高い段を「登録数」「級友が使った」など他人の行動に預けた。頑張る学生が自分の仕事の質で上限まで登れる作りになっていない。
6. **利用者自身の案を捨てた・崩した**。週28時間を超えない管理ツール、出席カウント、Excel などオフィス系でスマホ完結、Google だけで完結する一連の仕事（Web講演会の構想。動画は除く）、FAQ。これらを思想ごと受け継いでいない。
7. **水準がぶれた**。フェルミ推定・為替・BATNA のように高すぎるもの、確認メモのように低すぎるものが混在した。利用者は「レベル高すぎない」「要求水準は高い」の両方を言っている＝操作はスマホで無理なく、仕事の質で差がつく。

## 次のラウンドの必須条件

- 科目ごとに独立して成り立つ5個。他科目の成果物が無くても作れ、採点できる
- 各成果物は「新人が職場で実際に頼まれる仕事」の実物。場面・依頼者・使う場面を1行で言える
- 依頼者や顧客は実在させなくてよい（受託・報酬は禁止）。その代わり、成果物そのものが実務でそのまま使える品質であること。自分の生活・学業で実際に使う物は本物として認める
- 科目ごとに必須7種（Gemini Notebook・スプレッドシート・ドキュメント・スライド・画像生成・フォーム・ドライブ）を5個の中で積み上げ、1→5で使い切る。成果物ごとに「既に使えるもの」「新しく加わるもの」を明記
- 上限（5・10・15・20・30点）に比例した量と深さ。上の段は本人の仕事の質だけで登れる
- 利用者の元案（28時間管理・出席カウント・オフィス系スマホ完結・Googleだけで完結する一連の仕事・FAQ）を、合う科目に必ず検討し、使わないならその理由を書く
- 科目の役割は崩さない: マーケティング＝人の行動を変える・商談力／AI演習＝AIで作る・実装力／リテラシー＝安全・適法・継続的に運用する・運用力
- 動画なし、スマホ完結（フォームはブラウザ）、個人アカウント、報酬・受託なし、月で区切らない
