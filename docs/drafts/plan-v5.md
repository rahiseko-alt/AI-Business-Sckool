# 成果物15個 案 v5（指揮役、2026-09-28）

v4からの変更点（v4は却下。理由: 提出物の実物・採点条件が書かれておらず、作成から採点までのサイクルが見えなかった。曖昧な採点条件はAIの揺らぎに影響される、との指摘を反映）:

1. 各項目に**ビジネスシーン**を明記
2. 各項目を**段階点**（基礎点＋加点）に統一。○✖の二択をやめ、頑張った分だけ差がつく設計にする
3. 採点条件を**決定条件**（キーワード一致・数値照合・API値照合など、AI/スクリプトで判定できる形）まで具体化する。曖昧な言い換えの検出だけ人の最終確認を残す

列の意味:
- **成果物の実物**: 学生が実際に提出するファイル・リンクの形
- **材料**: 教員が事前に用意して配布するもの
- **段階点**: 基礎点（再提出で必ず届かせる下限）＋加点（頑張った分だけ）
- **決定条件**: 採点者（人・AI・スクリプトのいずれか）が何を数えて判定するか

## マーケティング（16回・商談力）

### 1（上限5）検索トレンド読解→PREP案内文
- ビジネスシーン: 新規出店・新商品提案前の需要調査レポート
- 成果物の実物: Googleドキュメント1枚（PREP構成、数値の出典明記）
- 材料: 指定検索キーワード・比較対象（期間・地域）、正解となる「読み取るべき傾向」
- 段階点: 基礎3（PREPの型・出典明記・誤字ゼロ）＋加点2（期間と地域の両方を比較+1／数値解釈が正解傾向と一致+1）
- 決定条件: PREP各要素の見出し有無（文字列）／出典URL記載／数値と正解データの一致率

### 2（上限10）口コミ集計→改善提案1枚
- ビジネスシーン: 店長会議向け競合比較レポート
- 成果物の実物: 集計スプレッドシート＋提案ドキュメント1枚
- 材料: 複数店舗の口コミデータ（件数の少ない店・古い口コミの罠入り）
- 段階点: 基礎6（集計値が正しい・罠データを除外できている）＋加点4（提案が集計値と対応+2／提案が実行可能な具体策+2）
- 決定条件: 集計値の正解一致（誤差0）／提案文中の数値と集計表の一致

### 3（上限15）調査フォーム設計→集計→ターゲット決定
- ビジネスシーン: 新商品発売前の顧客アンケート
- 成果物の実物: Googleフォーム＋回答集計スプレッドシート＋ターゲット決定ドキュメント1枚
- 材料: 罠入り回答データ（締切後・重複・テスト回答）、全設問形式を使う指定
- 段階点: 基礎9（全設問形式を使用・罠データを正しく除外・ターゲットが集計と対応）＋加点6（割合の丸め方が正しい+3／人物像が具体的+3）
- 決定条件: 設問形式チェックリスト／集計値の正解一致／除外すべき行数と実際の除外数の一致

### 4（上限20）アクセス解析→施策提案スライド
- ビジネスシーン: ECサイト運営者への売上改善提案
- 成果物の実物: スライド5枚程度（閲覧者共有）
- 材料: GA4デモアカウント（Google Merchandise Store）の指定期間データ
- 段階点: 基礎12（ユーザーとセッションを区別・期間設定が指定通り・グラフ数値が正解と一致）＋加点8（提案が特定数値を根拠にしている+4／経路・端末別の違いに言及+4）
- 決定条件: スライド内指標名と正解値の照合／提案文中の数値とグラフの一致／トンマナ基準（色・フォント・レイアウト）

### 5（上限30）最終課題

## AI演習（実践）（18回・実装力）

### 1（上限5）ルールブック＋張り紙
- ビジネスシーン: 新人研修の社内規程掲示物作成
- 成果物の実物: ルールブックのGoogleドキュメント＋張り紙（スライドかドキュメント1枚）
- 材料: 規程原文（閲覧のみ）、張り紙の仕様（A4縦・フォントサイズ）
- 段階点: 基礎3（必須項目網羅・誤字ゼロ）＋加点2（レイアウト条件+1／読みやすさ数値条件+1）
- 決定条件: 必須キーワード網羅（文字列一致）／校正ツールのフラグ数0（専門用語は除外リストで事前登録）／トンマナ基準（色・フォント・レイアウト、番号位置含む）

### 2（上限10）画風変換（同条件3枚）
- ビジネスシーン: 広告素材のブランドガイドライン準拠量産
- 成果物の実物: 画像3枚（指定形式で共有フォルダに提出）
- 材料: 元のゴシック調画像、変換後に保つべきポイント（数・位置・文字・色）
- 段階点: 基礎6（指定ポイントを3枚とも維持・文字崩れ無し）＋加点4（3枚の再現性=ポイントのブレが閾値内+4）
- 決定条件: 指定ポイントの座標・色コード照合（許容誤差つき）／3枚間の差分が閾値内か／トンマナ基準の配色範囲内か

### 3（上限15）ファクトチェック→説明文書き直し
- ビジネスシーン: 広報の社外発信文チェック
- 成果物の実物: PREP構成のドキュメント1枚＋ファクトチェック記録表＋Gemini/ChatGPT比較記録
- 材料: 誤りを仕込んだ元文章、正解の誤り箇所リスト（教員のみ保有）
- 段階点: 基礎9（仕込まれた誤りを全検出・PREPの型・事実誤りゼロ）＋加点6（2AIの回答差を具体的に記録+3／平易な言葉遣い+3）
- 決定条件: 検出箇所と正解リストの一致数／PREP見出しの有無／専門用語の使用数が閾値以下

### 4（上限20）雑スライド→正しいスライド10枚
- ビジネスシーン: 殴り書き資料の正式配布資料化
- 成果物の実物: スライド10枚前後（うち指定2枚は同条件で再度作成し再現性を提出）
- 材料: 雑スライド8枚、正しい集計表、スライド制作ルール
- 段階点: 基礎12（集計表と数値一致・重複統合・1枚1話）＋加点8（制作ルール完全準拠+4／指定2枚の再現性が閾値内+4）
- 決定条件: グラフ数値と集計表の照合／制作ルールのAPI値チェック（番号・括弧・箇条書き数）／トンマナ基準

## ビジネス情報リテラシー（19回・運用力）

### 1（上限5）日程変更メール返信
- ビジネスシーン: 取引先との日程調整（営業事務）
- 成果物の実物: 教員テスト用アカウント宛に届く実メール1通（CC込み）
- 材料: 取引先とのメールスレッド5通（日時が矛盾する罠入り）、共有資料1つ
- 段階点: 基礎3（最新日時を使用・正しいCC・添付でなくリンク共有）＋加点2（予約送信+1／閲覧権限を必要な人だけに限定+1）
- 決定条件: To/CC/BCC照合／本文中の日時が正解と一致／リンク共有権限のAPI照合

### 2（上限10）共有フォルダ整理
- ビジネスシーン: 前任者からの社内ドライブ引き継ぎ
- 成果物の実物: 整理後の共有フォルダ（教員に共有）＋報告メール1通
- 材料: ファイル30個ほど（名前ばらばら・重複・古い版・個人情報混入）、命名規則メモ
- 段階点: 基礎6（命名規則準拠・最新版の正しい特定・個人情報の外部共有なし）＋加点4（旧版を「旧版」フォルダへ退避+2／報告メールの変更点が具体的+2）
- 決定条件: ファイル名のパターンマッチ／共有権限のAPI照合／個人情報ファイルの共有範囲チェック

### 3（上限15）Meet討論→議事録→ToDo→カレンダー
- ビジネスシーン: 打ち合わせ議事録作成・タスク管理
- 成果物の実物: 議事録ドキュメント（教員を閲覧者に共有）＋カレンダーのToDo登録（教員招待）＋送付メール1通
- 材料: 討論テーマ（答えのない題）、招待手順書
- 段階点: 基礎9（教員が招待に含まれる・議事録が決定事項とToDoを区別・カレンダー登録に期限あり）＋加点6（版履歴で相互ホストが確認できる+3／ToDoの担当者が明記+3）
- 決定条件: カレンダーAPIで招待者・期限を照合／ドキュメント版履歴で両名の編集有無

### 4（上限20）調査写真整理→ナレッジページ
- ビジネスシーン: 現場調査結果の社内ナレッジ化
- 成果物の実物: Notionページまたはドキュメント1枚＋フォトアルバム（共有設定込み）
- 材料: 調査写真（顔・名札の写り込み、位置情報付きを含む）
- 段階点: 基礎12（顔・名札を処理・位置情報付き写真を除外・共有範囲が限定）＋加点8（ナレッジページが引き継ぎに使える構成+4／アルバムの命名・分類が規則通り+4）
- 決定条件: 画像のExif位置情報有無をスクリプトでチェック／共有設定のAPI照合
