# 0001 推測で確定しない・止まる・追跡できる

- 状態: 採用
- 日付: 2026-10-01

## 背景

成績は誤りが許されず、後から根拠を説明できなければならない。AI の判断精度に依存すると、
誤りがそのまま確定し得る。

## 決定

1. 計算・ID 照合・範囲/欠損/重複チェック・ABCDE 変換は決定論的なプログラムで行う。AI は候補の提示
   （資料分類・列の意味・表記揺れ・異常・曖昧箇所の説明）だけを担い、AI の出力は確定値にしない。
2. 確定の根拠は「規則による一致」か「Decision Log に保存したユーザー回答」の2つだけ。
3. 次のものは BLOCKED とし、未解決なら工程の進行役が次へ進ませない:
   同姓同名で識別不能／学籍番号不明／採点ルール不明／空欄の意味不明（空欄・0・未提出・欠席・
   未採点・対象外を同一視しない）／資料間の不一致／科目不明／異常値。
4. 名寄せの LIKELY・AMBIGUOUS・UNMATCHED は確定値として使えない（DB 制約で拒否）。
5. 採点ルールは科目ごとに独立。資料か回答の根拠が無いルールは登録できない（DB 制約で拒否）。
   別科目のルール流用・ABCDE 基準の推測・平均値等による補完は禁止。
6. 元資料・raw_records・evidence・decisions・audit_logs は追記専用。修正は original_value /
   corrected_value / reason / decision_id を残す別行で表す。
7. すべての得点は evidence（資料・シート・セル・原文の値）を持ち、最終評価から元のセルまで逆引きできる。
8. BLOCKED・未確認の同姓同名・ルール不明・資料間矛盾・計算不能が1件でも残る場合、
   完成版の成績表は出力しない。
9. システムは丸めない。計算は厳密な分数で行い、合計もそのまま保持・表示する（小数点は最終的に人が調整する）。
   評価は丸めない合計で判定し、人が整数に切り上げ・切り捨てると評価が変わり得るものは WARNING として監査一覧に出す。
   採点ルールに端数処理を持たせることもできない。
10. 最終出力は両学科で1ファイル（シート: AI計算版_学科／原本_学科／E一覧_学科・E一覧_統合／個人別評定_学科）。
    先生ごとの計算根拠シートは作らない（利用者の指示）。
    AI計算版は原本を丸ごと写し、利用者が指定した項目（出席点・態度点）のセルだけをシステムの計算値に置き換えて色を付ける。
    それ以外のセル（合計・評定などの式を含む）は原本のまま。原本シートには手を付けない。
    AIのセルには数字を貼り付けない。出席簿の月別シートを同じファイルに丸ごと写し、出席集計シート（出席簿を数える式）を
    参照する式にする。出席簿を直せば点数も変わり、セルをたどれば元の 欠・遅 に行き着く。
11. 出力は生成のたびに検算する（`src/grading/validation/workbook_check.py`）。出席簿のセルを直接数え直した値・原本・
    Python で計算した集計と全件照合し、1件でも食い違えば出力を「検算不合格」の名前に変えて使えなくする。
    利用者に渡す前に、別のAIによる独立レビュー（`.claude/agents/grading-reviewer.md`、外部AI向けは
    `scripts/make_review_packet.py`）も行う。
12. 学生の個人情報を含む資料・DB・出力は Git に入れない（`data/` を除外）。

## 結果

止まる回数は増えるが、誤った成績が黙って確定する経路を構造的に塞ぐ。
`/code-review` の Standards 軸はこの ADR への違反を「違反」として扱う。
