## リテラシーはこの思想でいい

今回のDrive教材は捨てない。ただし、**「教材の目次＝授業の目次」にしない**。

IPAのDSS-Lを見ると、現代の一般ビジネスパーソンに必要なものはかなりはっきりしている。AI、ハード・ソフト、ネットワーク、データ、ツール利用、セキュリティ、モラル、コンプライアンスが一つの体系になっている。 

しかも現在のDSS-Lは、生成AIについて**文章・画像・音声生成、プロンプト**まで明示し、ツール利用として扱っている。  セキュリティではパスワード、アクセス権、暗号、OTP、生体認証等、モラルではSNS・生成AIへの入力による情報漏洩、著作権・個人情報等まで含む。 

つまり、**ユーザーの感覚の方が正しい**。

学校教材の、

-  DB構築・DBMS **p.28–35** 
-  システム構成・評価 **p.60–67** 
-  システム開発・アルゴリズム・プログラミング **p.76–87** 
-  プロジェクト／サービス管理・監査など **p.88–99** 

を全員に順番に深く教えるより、必要時に「こういう仕事・仕組みがある」と紹介する程度に落とす。これは開発者育成ではなく、**日本で働く／事業をする学生のデジタルリテラシー教育**だから。

ただし学校側が「ITパスポート試験範囲を網羅すること」を科目要件にしているなら話は別。その場合は補講・自習範囲として残す必要がある。

## このシラバスの構造

最終的には単元の一本道ではなく、

**顧客を知る → 商品を決める → 価格を決める → 届ける → 知らせる → 売る → 数字を見る → 改善する**

を一度学び、2月からもう一度自分たちで回す構造になっている。

その横でAIは、

**質問する → 作る → 比較する → 分析する → ワークフロー化する**

まで難易度が上がる。

リテラシーは、

**PC・ネットの基礎 → セキュリティ → 法・モラル → AIリテラシー → 実務で安全に使う**

まで上がる。

この3本なら、かなり一貫したシラバスになる。特に\*\*「月曜に理論、火曜にAIで実行、金曜に安全性・正しさを確認」\*\*という科目間の役割分担が明確になる。

その考え方でよいです。むしろ今回のシラバスなら、**「中間試験・期末試験」という大きな試験を2回やる方式より、到達度確認を細かく分割して改善ループにする**方が授業設計と整合します。

## 1. 評価制度の基本形

学校の基準に合わせて100点満点をこうします。

| 評価区分配点方法 |          |                  |
| -------- | -------- | ---------------- |
| 中間評価     | 30点      | 前半3回の到達度テスト ×10点 |
| 期末評価     | 30点      | 後半3回の到達度テスト ×10点 |
| 課題提出     | 30点      | 6回の成果物 ×5点       |
| 学習態度     | 10点      | 授業活動・改善行動等       |
| **合計**   | **100点** |                  |

つまり、名称は「中間30・期末30」ですが、

**30点の中間試験を1回やるわけではない。**

前半：

> 到達度テスト① 10点
>
> 到達度テスト② 10点
>
> 到達度テスト③ 10点
>
> ＝中間30点

後半：

> 到達度テスト④ 10点
>
> 到達度テスト⑤ 10点
>
> 到達度テスト⑥ 10点
>
> ＝期末30点

です。

これなら「中間」「期末」は**成績処理上の区分**にすぎません。

---

# 2. 改善ループの中心は「合格するまで」

ここが今回のシラバスの重要部分です。

授業を、

**教える → やってみる → テスト → 間違いを確認 → 修正 → 再テスト → 合格 → 次へ**

にします。

例えばマーケティングなら、

> STPを学ぶ
>
> ↓
>
> AIで実際にターゲットを考える
>
> ↓
>
> 10分程度の確認テスト
>
> ↓
>
> 6/10点
>
> ↓
>
> 「セグメンテーションとターゲティングの違い」が理解できていない
>
> ↓
>
> 該当部分を復習＋課題を修正
>
> ↓
>
> 再テスト
>
> ↓
>
> 8/10点
>
> ↓
>
> 合格

という形です。

これは単なる「テストを何回もやる」のではなく、

**テストを診断装置として使う**

という設計です。

# 3. 合格基準

私は**70％を最低到達ライン**にするのがいいと思います。

| 得点扱い |              |
| ---- | ------------ |
| 9〜10 | 十分理解している     |
| 7〜8  | 合格・次へ進む      |
| 0〜6  | 未到達・復習して再テスト |

再テストの回数自体では減点しません。

**最終的に到達できたかを評価する。**

これが重要です。

1回目で10点を取った学生と、3回やって10点になった学生は、最終的な知識としてはどちらも10点です。

「早くできた人を評価したい」という部分は、テストではなく課題や学習態度で評価した方が制度がきれいです。

---

# 4. 全員が合格するまで授業を止めない

ここは実装上かなり重要です。

「全員がテストに受かるまで次の授業に進まない」にすると、授業が破綻します。

なので、

**クラス全体の進行と、個人の改善ループを分離します。**

通常授業は予定通り進める。

未合格者だけ、

> Google Classroom
>
> ↓
>
> 復習教材
>
> ↓
>
> Google Forms確認テスト
>
> ↓
>
> 不合格
>
> ↓
>
> 該当部分再学習
>
> ↓
>
> 再受験

とします。

これなら外国人留学生で理解速度に差があっても運用できます。

そして**月曜が祝日になる週を「補強・再挑戦週」として使える**。

前に問題になっていた祝日が、むしろこの制度ではバッファになります。

# 5. 6回の到達度テスト

マーケティングなら例えばこうです。

| 回時期到達度テスト配点 |       |              |        |
| ----------- | ----- | ------------ | ------ |
| ①           | 10月下旬 | 顧客・ニーズ・STP   | 10     |
| ②           | 11月中旬 | ブランド・差別化・商品  | 10     |
| ③           | 12月中旬 | 価格・流通・販促     | 10     |
|             |       | **中間評価**     | **30** |
| ④           | 1月下旬  | デジタルマーケティング  | 10     |
| ⑤           | 2月中旬  | 一連のマーケティング設計 | 10     |
| ⑥           | 3月初旬  | 結果分析・改善      | 10     |
|             |       | **期末評価**     | **30** |

前半・後半それぞれでほぼ均等に配置します。

今の実授業日程なら、マーケティング16回に対して例えば、

**10/26 → 11/16 → 12/14 ｜ 1/25 → 2/15 → 3/1**

くらいの間隔がかなりきれいです。

しかも100分授業を「試験日」にする必要はありません。

**授業の最初または最後の15〜20分で十分**です。

# 6. AIも同じ構造にする

火曜AI18回なら、ほぼ3授業ごとにテストできます。

| 評価内容例 |                   |
| ----- | ----------------- |
| AI①   | AIの基本・良い質問        |
| AI②   | 情報収集・検証           |
| AI③   | 生成・比較・改善          |
| AI④   | データ分析・マルチモーダル     |
| AI⑤   | ワークフロー・複数ステップ処理   |
| AI⑥   | マーケティング課題をAIで一連実行 |

AIは特に筆記試験だけにしない方がいいです。

例えば、

> 「このプロンプトの問題点を3つ直してください」
>
> 「AIの回答のどこを確認する必要がありますか？」
>
> 「このターゲット向けに広告を作り、なぜこの内容にしたか説明してください」

のような**実技型テスト**を含める。

金曜19回も、

| 評価内容例 |               |
| ----- | ------------- |
| IT①   | PC・OS・ネット     |
| IT②   | セキュリティ        |

>

>
> この画像を広告に使ってよいか？
>
> このグラフからこの結論を出してよいか？

のようなケース問題にする。

# 8. 課題提出30点も改善可能にする

ここもテストと思想を揃えます。

**6成果物 ×5点 = 30点**

にすると分かりやすいです。

マーケティングなら、

| 成果物例 |                    |
| ---- | ------------------ |
| ①    | 顧客・ペルソナ            |
| ②    | STP・ポジショニング        |
| ③    | 商品・価格              |
| ④    | 広告・販売計画            |
| ⑤    | デジタル施策             |
| ⑥    | 最終マーケティング計画・改善レポート |

そして、

**提出 → 教員フィードバック → 修正 → 再提出**

を認める。

これも改善ループです。

単に「出したから5点」ではありません。

---

# 9. 学習態度10点

ここは画像の「出席そのものを点数化することへの留意」とも整合させた方がいいです。

単純に、

> 出席90％＝10点

にはしない。

例えば、

| 項目点            |        |
| -------------- | ------ |
| 授業内活動・実習に取り組む  | 3      |
| 課題・テストの改善に取り組む | 3      |
| グループ活動・フィードバック | 2      |
| 準備・期限・授業ルール    | 2      |
| **合計**         | **10** |

とする。

つまり評価したいのは、

**「教室に座っていたか」ではなく、「学習活動をしたか」**

です。

# 10. これでシラバス自体がループになる

今回の授業は、

**月：マーケティングで考える**
**
→ 火：AIで実行する**
**
→ 金：リテラシーで安全性・正確性を見る**
**
→ 到達度テスト**
**
→ 弱点を発見**
**
→ 修正**
**
→ 再テスト**

になります。

そして数週間単位では、

**顧客 → 商品 → 価格 → 販促 → 販売 → 結果**

まで進んで、

**結果が悪い**
**
→ どこが悪かった？**
**
→ 上流へ戻る**
**
→ 修正する**

というマーケティング自体の改善ループにもなる。

つまり、

> **授業の学び方そのものが、授業で教えている「改善する」という考え方と同じ構造になる。**

ここまで統一するとかなり強いです。

シラバスには「中間試験」「期末試験」とだけ書かず、

**中間評価30点：前半に実施する3回の到達度確認（各10点）**
**
期末評価30点：後半に実施する3回の到達度確認（各10点）。各確認は到達基準に達するまで再学習・再確認を行う**

と明記するのがよいです。

次はこれを、さっき作った**10/1〜3/31の実日付シラバス表に「到達度テスト①〜⑥」「課題①〜⑥」まで埋め込めば完成形**にできます。

期末試験だけは試験としてやらねばならない。 時間は30分でも良い

他の科目と足並みを揃える。 ココはペーパーテストで、科目毎。

それなら評価設計はこう固定するのがよいです。

| 評価項目配点実施方法 |          |                   |
| ---------- | -------- | ----------------- |
| 中間評価       | **30点**  | 小まめな到達度テストを半期中に分散 |
| 期末試験       | **30点**  | **科目ごとのペーパーテスト**  |
| 課題提出       | **30点**  | 成果物・課題            |
| 学習態度       | **10点**  | 授業内活動・取り組み        |
| 合計         | **100点** |                   |

ポイントは、**「中間評価」と「期末試験」は性質を変える**ことです。

### 中間評価30点＝改善のためのテスト

例えば各科目、

**6回 × 5点＝30点**

にします。

約2〜3授業ごとに、

> 学習
>
> → 小テスト
>
> → 未到達部分を確認
>
> → 復習
>
> → 再テスト
>
> → 合格

を繰り返す。

ここがシラバスの**改善ループ**になります。

再テストを認め、最終的に理解できた点を中間評価点にする。つまり「最初からできたか」ではなく、**到達したか**を見る評価です。

---

### 期末30点＝正式な試験

ここは他科目と足並みを揃える。

-  マーケティング：マーケティングのペーパーテスト 
-  AI基礎：AI基礎のペーパーテスト 
-  ITリテラシー：ITリテラシーのペーパーテスト 
- **各30分程度** 
-  それぞれ独立して実施 
-  30点満点 

ここでは改善ループを回しません。

むしろ、

**それまで何度も復習・再テストしてきた結果、本当に知識が定着しているか**

を最後に確認する試験にします。

つまり全体は、

> **形成評価30点**
>
> 小テスト→失敗→学び直す→再挑戦
>
> **総括評価30点**
>
> 最後に一人でペーパーテスト

という構造になります。

これはかなり筋が通っています。

### 課題30点との役割も分ける

さらに整理すると、

**小テスト30点＝分かっているか**

**期末試験30点＝身についているか**

**課題30点＝使えるか**

**態度10点＝学習に取り組んだか**

です。

今回の3科目統合授業には、この4分割が非常にきれいに合います。

特にAIは実技中心になりますが、期末だけは他科目と同様にペーパーにして、

-  AIに入力してはいけない情報はどれか 
-  良いプロンプトはどちらか 
-  AIの回答をそのまま信用してはいけない理由 
-  ハルシネーションとは何か 
-  AIを使った業務の正しい手順 

など、**AIを操作しなくても理解度を測れる問題**にすればよいです。

シラバス上の正式表記も、

> **中間評価（30%）：授業期間中に複数回実施する到達度確認テスト。未到達の場合は再学習・再確認を行う。**
>
> **期末試験（30%）：学期末に科目ごとの筆記試験を実施する。**

とすれば、学校の「中間30・期末30」という枠も壊しません。

次にシラバスを作るときは、**6回の小テストを実際の日付に配置し、各回で「何を合格基準にするか」まで入れる**のがよいです。

# 取得上の制約

現時点のチャット履歴検索は、過去会話の存在・日時・一部発言を検索できますが、すべての過去チャットについて「ユーザー発言＋アシスタント発言の全文」を一括で返す機能ではありません。したがって、上の一覧で「全文原文は取得不可」とした会話については、このファイル内で勝手に補完していません。

ChatGPTのデータエクスポートに含まれる会話履歴（例: `conversations.json` / エクスポートHTML）があれば、そこから「シラバス」に関係する全会話を抽出し、ユーザー・アシスタント双方の発言を一字一句そのまま、完全な時系列Markdownへ統合できます。
